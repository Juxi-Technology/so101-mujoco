# 02 · 시뮬레이션 모델 검증(MJCF 로드와 구동)

## 모델 출처

SO-ARM101의 공개 MJCF 모델 세 가지를 모두 검증하여 사용 가능함을 확인했습니다:

| 약칭 | 파일 | 출처 |
| --- | --- | --- |
| 공식-신규 캘리브레이션 | `SO101/so101_new_calib.xml` | TheRobotStudio/SO-ARM100 공식 저장소; **이 저장소의 튜토리얼 zip 안에 동일 사본 포함**(바이트 단위 일치) |
| 공식-구 캘리브레이션 | `SO101/so101_old_calib.xml` | 동일 저장소(zip에는 없음, 다운로드 필요) |
| ROS2 디스크립션 패키지 | `so_arm101_description/mjcf/so_arm101.xml` | 이 저장소 튜토리얼 첨부 파일 `SO-ARM101_ROS2.zip` |

참고: zip 추출 흐름은 초기 버전 `so101_assets.py`에서 제공되며 조회 가능한 상태로 유지되어 있습니다. 2026-10-16부터 시뮬레이션 로봇은
**mujoco_menagerie의 SO-ARM100 모델**로 이전되었습니다(`assets/menagerie_so_arm100/`에 vendored,
이전 이유와 요점은 [07](07-troubleshooting.md) 설계 설명 참조).

## 구동 및 렌더링 검증

```bash
export UV_CACHE_DIR='C:\Users\admin\AppData\Local\Temp\uv-cache'
uv run --frozen --with mujoco python examples/so101_mujoco/load_and_drive.py \
    --model "<模型路径>" --out-dir out
```

스크립트는 구조 요약(관절/액추에이터/게인/범위)을 출력하고, "6개 관절 순차 스윕 + 조화 사인" 검증 영상과 정지 프레임을 렌더링합니다.
구조 요약 샘플은 `reports/`에 있으며(저장소에 포함), 비교 영상(`media/`)은 용량이 커서 저장소에 배포하지 않습니다. 위 명령으로 언제든 다시 생성할 수 있습니다.

## 세 모델의 핵심 차이(실측)

| 항목 | 공식-신규 캘리브레이션 | 공식-구 캘리브레이션 | ROS2 디스크립션 패키지 |
| --- | --- | --- | --- |
| 영점 의미 | 관절 **스트로크 중간점** | 수평 **완전 신전** 위치 | 스트로크 중간점 |
| 관절 이름 | `shoulder_pan` | 왼쪽과 동일 | `shoulder_pan_joint`(접미사) |
| 위치 게인 | kp=998.22, kv=2.731 | **kp=17.8, kv=0** | kp=998.22 |
| 그리퍼 단위 | 라디안 hinge | 라디안 hinge | **0~1 정규화** |
| 자기 충돌 제외 | 없음 | 없음 | 있음(6쌍) |

**추종 오차 실측**: 신규 캘리브레이션과 디스크립션 패키지는 정지 유지 오차 0.0005 rad, 구 캘리브레이션은 0.03 rad(처짐 약 1.7°, kp가 56배 약함)입니다.
시뮬레이션에서 동일한 정책을 평가해도 모델을 바꾸면 다른 동역학이 나오므로, 어느 모델을 사용했는지 기록해 두어야 합니다.

## 반드시 기억해야 할 모델 동작

1. **`shoulder_lift`의 양의 방향은 아래쪽**: 구동 토크에서 "하방 스윙"이 양의 각도를 사용하므로, 텔레오퍼레이션 매핑이나 데이터 변환 시 부호를 먼저 확인해야 합니다.
2. **바닥에 닿으면 정지**: 하방 스윙 한계에서 손끝이 지면에 닿아 멈춥니다(스크립트에 8cm 이격 보호가 내장되어 자동으로 진폭을 줄임).
3. 공식 모델에는 카메라와 keyframe이 없습니다. 카메라가 포함된 변형 `so101_new_calib_camera.xml`이 존재하며, 추후 비전 데이터 녹화에 사용할 수 있습니다.
