## 次のステップ（価値順）

### フェーズ 2 · カメラをシーンへ（進行中）

**完了したもの**：
- ブラケット（STEP→STL）とカメラ（HBVCAM-F2170HD V22 データシートの 25×30×5.2mm に基づくプレースホルダ）をシミュレーションに組み込み、
  姿勢は `adjust_mount.py` / `adjust_camera.py` で実機と照合しながら調整；
- `<camera>` 要素を接続（`sim_cam`、fovy 初期値 49°）、**シミュレーション視覚録画のパイプラインは開通済み**：
  `--robot.image_camera=sim_cam` で `observation.images.wrist` 動画データセットが生成される（スモークテスト [5] すべて通過）。

**2026-10-16 更新**：カメラの照準／fovy は満足のいくところまで調整済み（`adjust_camera.py` に **live view リアルタイム画面ウィンドウ**を追加、
中断からの再調整、ウィンドウを誤って閉じても自動再オープン；さらに MuJoCo カメラの画角方向 = **要素の −Z** による「レンズの向きと画面が逆」バグを修正、
詳細は [07](07-troubleshooting.md) 参照）。新しいキャリブレーションのリーダーアームで正式に視覚データセットを録画済み（wrist 動画含む、追従誤差 ≤2 単位）✅；
旧実験録画は 2026-10-16 に整理し、正式データセットは `so101_sim_vision`（デュアルカメラ）に統一。
**同日、シミュレーションロボットを mujoco_menagerie の SO-ARM100 モデルに移行**（2026-10-16）：元チュートリアルモデルの爪は掴めなかったが、
新モデルの爪部は実機 CAD の衝突で、実測で 34mm ブロックを安定して掴める；録画／遠隔操作／デュアルカメラ／ワークスペースのパイプラインはすべて維持し、
実機遠隔操作での再確認待ち（特に wrist_roll の方向符号）。
**未完了**：実機の HBVCAM を接続した後、「実機撮影 vs シミュレーションレンダリング」の対照微調整を行う；
オプション：カメラ本体の STL でプレースホルダを置き換え。実機側のカメラ設定（`--robot.cameras` OpenCV）も後日同様に実施。

### フェーズ 4 · 学習と展開

- ✅ **学習／展開パイプラインは実測済み**（2026-10-16）：`lerobot-train`（ACT、CPU 12 ステップスモーク——約 2s/ステップ、loss は正常に低下、
  checkpoint は期待どおりディスクに保存）と `lerobot-rollout --strategy.type=base`（シミュレーションで実際にポリシーを 20s 実行、
  自動でアームを初期姿勢に戻してから終了）がいずれも開通；完全なコマンド、要点、継続学習の方法は [09](09-usage-tutorial.md) の第 7/8 節、
  チュートリアル同梱のデモ checkpoint `outputs/train/smoke_act` をそのまま展開パイプラインの試運転に使える；
- 正式な学習は **GPU 搭載機**で行う（ACT / SmolVLA；本機は純 CPU で小ステップ数のパイプライン検証にのみ適する）；
  データセットはコピーするか HF のプライベートリポジトリにプッシュすればよい；
- 実機展開も同様に `lerobot-rollout` 経由（`--robot.*` を `so101_follower` 設定に置き換え）。

### 長期 · sim2real

シミュレーションデータ + 少量の実機データで混合学習 → 実機でのゼロコスト評価（シミュレーションでポリシーの成功率を再現可能に評価）。
注意：純シミュレーションデータをそのまま実機に載せる（ゼロショット転移）のが最も難しいルートであり、まず「短い閉ループ」（実機データで学習→実機展開）を行い、
シミュレーションを段階的に重ねる。
